# Technical overview

How the port is put together and how to build it. The bring-up history (every problem found and its fix) is in [BRINGUP.md](BRINGUP.md); testing on a tablet is in [INSTALL.md](INSTALL.md).

## 1. The device

- **SoC**: NVIDIA Tegra 4 (T114), 4x Cortex-A15, ARMv7, 32-bit only. 2 GB RAM, 11.6" 1920x1080 DSI panel.
- **Board**: NVIDIA's `macallan` reference platform (as the Asus Transformer Pad TF701T). Product `sk1wg`, `ro.hardware` `macallan`.
- **Stock**: Remix OS 2.0.305 (Android 5.1.1), NVIDIA Linux 3.4.108.
- **Bootloader**: fastboot, unlocked, `secure: no`: unsigned images boot, and `fastboot boot` runs an image from RAM.
- **Boot images**: Android v0 header, base 0x10000000, page size 2048. The bootloader passes its own command line and puts the boot image's in front of it.
- **Keyboard cover**: plain USB HID on the pogo contacts (VID 1017, PID 1006), plus a Hall switch for the lid on GPIO PK6.

## 2. Source trees and branches

The Android tree is LineageOS-UL 21 with the Galaxy Camera Revived forks for old 3.4 kernels, plus the tablet's own device tree and kernel. `manifests/sk1wg.xml` (this repo) lists the forks.

This repository holds what is not part of the Android tree: the docs, `manifests/`, `tools/` and the mini recovery sources (`minirecovery/`).

### The LineageOS-UL freeze

LineageOS-UL 21 stopped on 2025-04-04, and LineageOS kept changing afterwards. `manifests/zz-lineage-snapshot.xml` pins every `LineageOS/*` project to its last commit before 2025-04-05; it is the same file as Galaxy Camera Revived's, generated by that project's `tools/pin-snapshot.sh`. The security patch level is therefore 2025-03-01.

## 3. Building

### Host

Built on WSL2 Ubuntu 22.04, with the usual LineageOS build dependencies, `repo` and ccache. A full `m droid` from scratch takes about 2 hours with ccache (121k steps).

### Sync

```
mkdir -p ~/android/lineage-sk1wg && cd ~/android/lineage-sk1wg
repo init -u https://github.com/LineageOS-UL/android.git -b lineage-21.0 \
    -g default,-qcom,-device,-mips,-darwin,-notdefault --depth=1
mkdir -p .repo/local_manifests
cp <this repo>/manifests/sk1wg.xml <this repo>/manifests/zz-lineage-snapshot.xml .repo/local_manifests/
repo sync -c -j8
```

- Until the device tree and kernel are published, they are not in the manifest: put them in `device/jide/sk1wg` (branch `lineage-21.0`) and `kernel/jide/sk1wg` (branch `sk1wg`) by hand.
- With a Galaxy Camera Revived tree on the same disk, `repo init --reference=<that tree>` borrows its git objects. Keep the two trees separate: never build sk1wg in the Galaxy Camera's tree, so the two never share an `out/`.
- `repo sync` leaves `external/chromium-webview/prebuilt/arm/webview.apk` as a Git LFS pointer: run `git lfs pull` in that project.

### Blobs (never committed)

No proprietary file is in any of our repositories. `extract-files.sh` puts them in `vendor/jide/sk1wg` at build time, from the stock Remix OS 2.0.305 `/system`:

1. Unsparse the official `system.img` with `tools/simg2img.py` and dump it with `debugfs` (or loop-mount it read-only), so that you have a directory holding `system/`.
2. Extract:
   ```
   cd device/jide/sk1wg && ./extract-files.sh <dir holding system/>
   ```

`extract-files.sh` also patches a few bytes in NVIDIA's `gralloc.tegra.so` and `hwcomposer.tegra.so` (described in the script and in [BRINGUP.md](BRINGUP.md)). Each patch checks the original bytes first and fails on anything unexpected, so it only works with the 2.0.305 files.

### Build

```
source build/envsetup.sh
lunch lineage_sk1wg-ap2a-userdebug
m droid
```

- The kernel is built in-tree with `lineageos_sk1wg_defconfig` and the tree's GCC 4.9 (`arm-linux-androideabi-4.9`). The 3.4 tree's host tools need `-fcommon`, which the device tree passes.
- Outputs in `out/target/product/sk1wg/`: `boot.img`, `system.img` (flashed to APP), `system_ext.img` (flashed to CAC).
- `SK1WG_SDCARD_ROOT=true` in the environment builds the microSD variant (`rootdir/etc/fstab.macallan.sdcard`); only `boot.img` and `system.img` differ.
- Avoid a single-module `m <module>` between full builds: the next `m droid` then rebuilds most of the tree.
- The version reads `21-<date>-UNOFFICIAL-JideRemixTabletRevived-sk1wg`.

### Partitions

No repartitioning, ever: the GPT sits behind NVIDIA's BCT/PT area.

| GPT | Use | Size |
|---|---|---|
| LNX | boot | 8 MB |
| APP | system, with vendor inside (`/system/vendor`) | 1000 MB |
| CAC | system_ext (stock `/cache`) | 768 MB |
| UDA | data | ~56 GB |
| SOS | stock Remix OS recovery, untouched | 8 MB |
| MSC | misc | 2 MB |
| USP, MDA, DTB, BMP, LBP, CHG, FBP, FCG | never written | |

Why system_ext is on CAC: [BRINGUP.md](BRINGUP.md#partitions).

### Testing Remix OS on our kernel

Our kernel also boots the stock Remix OS (a regression test for the kernel), but Remix OS needs the 32-bit binder ABI: build with `CONFIG_ANDROID_BINDER_IPC_32BIT=y` (LineageOS 21 needs it off, the defconfig default), then `tools/repack-boot.sh <stock boot.img> <zImage> <out.img>` puts it in front of the stock ramdisk, and `fastboot boot <out.img>` runs it.

## 4. The mini recovery

`minirecovery/` is a small recovery image for **`fastboot boot` only** (it is never flashed): the stock 2.0.305 kernel and adbd, a static busybox as PID 1 (the stock Android 5.1 init would load SELinux and confine everything), a setuid `su` and `reboot-to`.

- `backup-critical`: read-only backup of everything except system, cache and userdata ([INSTALL.md](INSTALL.md#4-back-up-the-tablets-own-partitions)).
- `rootrun <command>`: runs a command as PID 1 with all capabilities. adbd keeps only CAP_SETUID/SETGID, so `su` can read block devices but cannot mount or reboot: use `rootrun reboot-to bootloader`, `rootrun mount -o ro ...`.
- `reboot-to bootloader|recovery`: the kernel knows only `recovery`, `bootloader` and `forced-recovery`. **Never use `forced-recovery`** (APX mode).
- No `fdisk`, on purpose.

Build it with `tools/build-minirecovery.sh <stock boot.img> <stock recovery.img> <busybox static ARM> <su static ARM> <out dir>` and `REBOOT_TO=<static ARM reboot-to>`. The static helpers (`minirecovery/su.c`, `minirecovery/reboot-to.c`) are built in an Alpine `linux/arm/v7` container. **The output contains Jide's binaries** (the stock kernel and adbd), so it is never committed.

Other tools: `tools/unpackboot.py` (unpack a v0 boot image), `tools/simg2img.py` (sparse to raw), `tools/busybox-applets.sh` (list an ARM busybox's applets without running it).

## 5. Debugging tips

- **A failed boot restarts into the bootloader** (init's fatal reboot, or a kernel panic with the bring-up's `TEGRA_PANIC_TO_BOOTLOADER`), and fastboot then answers without the key menu. RAM-boot the mini recovery and read `/proc/last_kmsg`: the kernel's RAM console keeps the previous boot's kernel and init log.
- **Pass `-s <serial>` to adb and fastboot** when another Android device is connected.
- **adb on test builds** starts at boot without the key prompt (USB `0955:7100`). `adb root` needs "Rooted debugging" in the developer settings.
- **The persisted logcat** (`/data/misc/logd`) survives a forced power-off only up to its last rotation; read it from the mini recovery (`rootrun` to mount UDA read-only).
- **Performance**: the system partition is full, so only the boot image and system_server are compiled ahead of time; `init.sk1wg.dexopt.sh` compiles the everyday apps into `/data` after the first boot. Until it has run, the UI is slow.
- Compare with stock before blaming the kernel: some warnings (camera GPIOs, for one) appear on the stock kernel too.

## 6. Known gaps before a public release

- **Bring-up aids still on**: adb without authentication on userdebug builds (`WITH_ADB_INSECURE`), adb kept in the "mtp" USB configuration on debuggable builds, the kernel's `oops=panic` and `TEGRA_PANIC_TO_BOOTLOADER`.
- **SELinux is permissive.** Before enforcing: types for the new device nodes (`/dev/ion`, `/dev/lightsensor`, the PM QoS nodes, `tegra_floor`, the backlight), the dexopt script's domain, and the kernel has no SELinux binder hooks.
- **The kernel is not flashed yet**; every boot is a `fastboot boot`.
- WebView's ANGLE flags are only written on debuggable builds; a user build needs another way.
- The gralloc lock-wait patch gives up the cross-process buffer lock's mutual exclusion (GPU access is still ordered by fences). The clean fix is to keep NVIDIA's HWC from locking the layers it never reads.
- No camera.
- The power HAL's clock floors and the EMC tuning: battery drain not measured yet.
- The `frameworks/base` boot animation fix is on a local branch only.
- The security patch level is frozen at 2025-03-01.
