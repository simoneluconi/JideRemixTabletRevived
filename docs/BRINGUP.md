# LineageOS 21 bring-up notes

Working notes for the first LineageOS 21 (Android 14) builds on the Jide Remix Ultra Tablet (sk1wg). They record what was measured and decided, so the next steps do not have to re-derive it.

## Trees

| Path (in `~/android/lineage-sk1wg`) | What |
|---|---|
| LineageOS-UL `lineage-21.0` | Base, synced with [`manifests/sk1wg.xml`](../manifests/sk1wg.xml) and Galaxy Camera Revived's `zz-lineage-snapshot.xml` (UL froze on 2025-04-04) |
| `kernel/jide/sk1wg` | Our kernel, branch `sk1wg` (see "Kernel" below). A local clone for now, to become a public GitHub fork |
| `device/jide/sk1wg` | The device tree (git repo, branch `lineage-21.0`) |
| `vendor/jide/sk1wg` | Generated by `extract-files.sh` from the stock 2.0.305 `/system`; never committed |

The tree is separate from the Galaxy Camera's `~/android/lineage` (it borrows its git objects with `repo init --reference`), so the two builds never share an `out/`.

## Kernel

NVIDIA's 3.4 macallan kernel, from the community CM13 port (TerenceWSK `cm-13.0`, 3.4.112), plus:
- Android 8+ backports from LineageOS's Shield Portable kernel (roth `lineage-15.1`): binder with the 64-bit ABI and binder/hwbinder/vndbinder, seccomp-bpf with TSYNC, no_new_privs, ambient capabilities, the new UID routing (FRA_UID_RANGE).
- From html6405's Exynos 3.4 kernel: getrandom, memfd_create, `sk_uid` and UID-based routing in the IP protocols, ARM 8-byte `get_user()`.
- Ours: syscall wiring, Android cpuset `allow_attach` and cpus kept across CPU hotplug (cpuquiet), the `rt_fill_info()` NULL fix, `sk_fullsock()`, `CONFIG_CMDLINE_EXTEND` for FDT boots.
- Defconfig `lineageos_sk1wg_defconfig`. It appends `androidboot.hardware=macallan androidboot.boot_devices=sdhci-tegra.3 androidboot.selinux=permissive` to the bootloader's command line.

An independent review (2026-11-06) found the RTM_GETROUTE oops and the missing socket UIDs; both are fixed. Still open, not needed to boot: SELinux binder hooks, `RTA_MARK` in the route policies, renameat2, eBPF.

Stock Remix OS uses the 32-bit binder ABI: to boot it on our kernel (a regression test), build with `CONFIG_ANDROID_BINDER_IPC_32BIT=y`.

## Graphics

NVIDIA's T114 blobs from Remix OS 2.0.305 (Android 5.1):
- **Link check against Android 14** (the Galaxy Camera's 32-bit LOS21 libraries): the 25-library closure of EGL/GLES/gralloc/hwcomposer only misses `android_atomic_{inc,dec,acquire_load,release_store}` (gralloc, hwcomposer) and one `GraphicBuffer` constructor (hwcomposer). Shims: `shims/atomic.c`, `shims/graphicbuffer.cpp`, wired with `TARGET_LD_SHIM_LIBS`.
- No text relocations in any of them.
- The EGL/GLES wrappers have `/system/lib/` built in; `extract-files.sh` rewrites it to `/vendor/lib/` (same length).
- `gralloc.tegra.so` has **no framebuffer device**, so the HWC2-on-fb fallback cannot work with it; the display needs `hwcomposer.tegra.so` (HWC 1.x) through `hwc2on1adapter`.
- `hwcomposer.tegra.so` uses `GraphicBuffer` in one place, `create_graphic_buffer()`: `operator new(128)` then the 5.1 constructor. Android 14's `GraphicBuffer` is **160 bytes** on 32-bit ARM, so `extract-files.sh` patches `movs r0, #128` at file offset 0xc11c to `#160` (Thumb `8020` -> `a020`, one byte). The shim builds Android 14's object there and `static_assert`s the size. Checked with the tree's compiler: the rest of what the blob touches is unchanged since 5.1 (it calls `RefBase::incStrong/decStrong` on the object pointer, RefBase at offset 0; `ANativeWindowBuffer` at offset 8; it reads `handle` at offset 60 of `getNativeBuffer()`; it passes `keepOwnership = false`).
- HIDL: allocator and mapper 2.0 (gralloc0 adapters from html6405's `hardware/samsung`), composer 2.1 with AOSP's `HwcLoader`, all passthrough, as on the Galaxy Camera.

Not in the first build: camera (`camera.tegra.so` needs the 5.1 libcamera_client/libgui ABI), the OMX video decoders (`libnvomx`, 5.1 libmedia/OMX ABI), the TLV320AIC325x audio HAL (`audio.primary.tegra.so`, libmedia), sensors (`sensors.macallan.so` + `libinvensense_hal`).

## Partitions

No repartitioning, ever (the GPT sits behind NVIDIA's BCT/PT area).

| GPT | LineageOS use | Size |
|---|---|---|
| LNX | boot | 8 MB |
| APP | system, with vendor inside (`/system/vendor`, `/vendor` a symlink) | 1000 MB |
| CAC | system_ext (stock `/cache`, not needed by LineageOS) | 768 MB |
| UDA | data | ~56 GB |
| SOS | stock Remix OS recovery, untouched | 8 MB |
| MSC | misc | 2 MB |
| USP, MDA, DTB, BMP, LBP, CHG, FBP, FCG | never written | |

**System size**: the Galaxy Camera's LOS21 system is 1120 MB (APEX 277, system_ext 220, product 147, app dexpreopt 57). For 1000 MB the sk1wg build uses `common_mini_tablet_wifionly`, preoptimises only the boot image and system_server, and drops phone, camera, updater and theme packages (`RemovePackages`). That still made 1210 MB (2026-11-07: system_ext 291, APEX 260, product 185 with WebView 90, framework 151, fonts 79), while the vendor files are only 33 MB. So system_ext went to CAC and vendor into system. The linker resolves its `dir.*` paths with `realpath`, so `/system/vendor` binaries still get the vendor namespace; the shims are matched on realpaths, hence the `/system/vendor/...` entries in `TARGET_LD_SHIM_LIBS`.

## Testing without touching Remix OS

`fastboot boot` only loads the kernel and ramdisk. For a full LineageOS boot there are two ways:
1. **Internal eMMC**: flash APP (`fastboot flash system system.img`) and CAC (`fastboot flash cache system_ext.img`). Remix OS's system comes back with `fastboot flash system system.img` from the official 2.0.305 zip, and CAC is only its cache. But LineageOS needs `/data` formatted, which loses Remix OS's data.
2. **microSD** (`SK1WG_SDCARD_ROOT=true`): `rootdir/etc/fstab.macallan.sdcard` mounts system, system_ext and data from the card's partitions 1-3. The eMMC is not written at all. The card is partitioned and written from the mini recovery (`mmcblk1` only).

## First boot procedure (internal eMMC)

Images: `device-dump/lineage-21-2026-11-07/` (`SHA256SUMS` beside them). Battery at 50% or more. The bootloader in "Fastboot Protocol" mode (Volume Up + Power, then pick it in the menu).

1. Zero-risk check first: the cmdline test (`fastboot boot device-dump/test-images/mr-cmdline-test/minirecovery.img`, then look for `sk1wg.cmdline_test=1` in `/proc/cmdline`).
2. Write system and system_ext, then wipe data (loses Remix OS's data):
   ```
   fastboot -S 256M flash system system.img
   fastboot -S 256M flash cache system_ext.img
   fastboot format:ext4 userdata
   ```
   `-S 256M` sends the sparse images in pieces (ours are 1010 and 306 MB; stock's system was 757 MB). `boot` (LNX) is **not** flashed yet.
3. `fastboot boot boot.img`. The build is userdebug with `WITH_ADB_INSECURE`: adbd starts at boot without the key prompt (USB 0955:7100), so `adb -s <serial> logcat` and `dmesg` work even if the display does not. The first boot compiles apps on the device: several minutes.
4. Only once it boots: `fastboot flash boot boot.img`.

Back to Remix OS: `fastboot flash system`, `fastboot flash boot` with the official 2.0.305 images, `fastboot format:ext4 cache`, `fastboot format:ext4 userdata`.

microSD variant: `device-dump/lineage-21-2026-11-07-sdcard/` (same sources, built with `SK1WG_SDCARD_ROOT=true`; only `boot.img` and `system.img` differ). It needs the card partitioned (p1 >= 1000 MB, p2 >= 800 MB, p3 rest) with the raw images on p1/p2 (`simg2img` first) and an empty ext4 on p3, then only `fastboot boot boot.img`. Still open: the mini recovery has no `fdisk` (left out on purpose), so the card is best prepared on the PC (a reader passed to WSL with `usbipd`) or with a partitioning helper that refuses anything but `mmcblk1`.

## First boots (2026-11-07)

System and system_ext flashed to APP and CAC, userdata formatted, boot only RAM-booted. Each failed boot ends in init's `InitFatalReboot`, a reboot to the bootloader; the log is read with the mini recovery from `/proc/last_kmsg` (saved in `device-dump/test-runs/los21-boot*-last_kmsg.txt`). The kernel's gaps, in the order the boot hit them:

| # | Where | Error | Fix (kernel branch `sk1wg`) |
|---|---|---|---|
| 1 | first stage, mounting /system | `failed to realpath(/system): Bad file descriptor` | bionic's `realpath()` `fstat()`s an `O_PATH` fd, allowed only since Linux 3.6: `vfs_fstat()` takes `fget_raw_light()` (upstream 55815f70147d) |
| 2 | loading SELinux policy | `SELinux: avtab: invalid type or class` | the CM13 tree had switched back to Android M's ioctl whitelisting format; reverted that, so the kernel reads upstream xperms (policy version 30) as Android 7+ writes them |
| 3 | second stage, `SetupMountNamespaces` | `Cannot open fd for current mount namespace` | `setns()` for mount namespaces and `/proc/<pid>/ns/*` as symlinks with inode numbers (Linux 3.8; roth's picks of 8823c079ba71, 33d6dce60757, bf056bfa8059, 98f842e675f9 and the proc_free_inum fix) |
| 4 | `SetMmapRndBits` | `Cannot open for reading: /proc/sys/vm/mmap_rnd_bits` | roth's ARCH_MMAP_RND_BITS backport (Linux 4.5); init raises it to 16 bits itself. Also `CONFIG_HW_RANDOM` for prng_seeder's `/dev/hw_random` |
| 5 | adbd | host sees the device "offline" | the 3.4 f_fs has no AIO: adbd's legacy blocking USB code (`ro.adb.nonblocking_ffs=false`, `sys.usb.ffs.aio_compat 1`; device tree) |
| 6 | SurfaceFlinger, Skia RenderEngine | `Failed to create a valid texture` in `primeShaderCache` | `debug.renderengine.backend=gles` (device tree, as smdk4412-common) |
| 7 | GLES RenderEngine | every shader fails to compile, empty info log | `libcgdrv.so` (NVIDIA's GLSL compiler, dlopen()ed by `libGLESv2_tegra_impl.so`) was missing from `proprietary-files.txt` |
| 8 | any process death | `binder: unknown command 0`, servicemanager and hwservicemanager abort | `BC_DEAD_BINDER_DONE` skipped `sizeof(void *)` (4) instead of the 8-byte cookie (kernel) |
| 9 | SurfaceFlinger, first shader | SIGSEGV at 0x10001 in `libGLESv2_tegra_impl.so` | `libnvcpl.so`/`libcplconnectclient.so` build an Android 5.1 `android::Parcel` on their stack; Android 14's is bigger and overwrote the caller's saved registers. Replaced by binder-free stubs (`shims/nvcpl_stub.c`) that report "not available" |
| 10 | system_server, PackageManager | `There must be exactly one permissions manager; found []` | apexd's `realpath()` on a binder thread: with `/proc` at hidepid=2, 3.4 refused sub-threads their own `/proc/self/fd`. Kernel: "__ptrace_may_access() should not deny sub-threads" (73af963f9f30) and the `proc_fd_permission()` thread fixes (96d0df79f264, 54708d2858e7) |
| 11 | bootanimation, `eglCreateWindowSurface` | SIGSEGV in `NvGrLock()` at header page + 0x48; RenderEngine `EGL_BAD_ALLOC` | NVIDIA's gralloc keeps the allocating pid in the handle (offset 0x14) and skips the mapping for "its own" buffers; Android 14 imports a clone in the allocating process and frees the original. The mapper clears that pid on its clone (`interfaces/mapper/Gralloc0Mapper.cpp`) |
| 12 | system_server, AlarmManager | `kernel does not support timerfd_create() with alarm timers` | timerfd alarm clocks and CLOCK_BOOTTIME (html6405's picks of 11ffa9d6065f, 4a2378a943f0) plus the alarmtimer helpers they need, written for 3.4's per-base timer |

| 13 | system_server, LockSettingsService | keystore2: `Cannot check permission without calling_sid`, then `Failed to import secret key` | binder sender security context (upstream ec74136ded79 with its overflow and SG-end follow-ups, as html6405 has them): `FLAT_BINDER_FLAG_TXN_SECURITY_CTX`, `BINDER_SET_CONTEXT_MGR_EXT`, `BR_TRANSACTION_SEC_CTX` |

| 14 | right after boot | black screen with the backlight on; SurfaceFlinger loops on `GetBufferLock timed out ... LockState -1`, system_server's `android.ui` blocked in `SurfaceControl.nativeCreate()`, Watchdog kills system_server every minute | bootanimation is stopped while it holds a buffer's cross-process write lock. `extract-files.sh` patches `NvGrLock()` so a lock still held after the 2 s timeout counts as abandoned (`LockState = 0`, check again) |
| 15 | first frames after boot | SurfaceFlinger SIGSEGV in `gralloc.tegra.so` (header + 0x70) from `hwcomposer.tegra.so` in `HWC2On1Adapter::Display::present()` | the composer HAL frees a replaced layer buffer while NVIDIA's HWC 1.x still uses it; the mapper keeps the last 4 freed handles registered before releasing them |

**2026-11-07 16:26** (kernel fix13, system fix15): boots to the LineageOS setup wizard; SurfaceFlinger stable, a `screencap` shows the wizard correctly at 1920x1080.

**2026-11-07 16:07: first complete boot** with kernel fix13 and system fix11: `sys.boot_completed=1`, SurfaceFlinger "Boot is finished (40058 ms)", system_server phase 1000, SystemUI started. The boot animation shows but its textures are garbled (the gradient and the three circles are right, the logo and text bitmaps are scrambled), which points at texture uploads rather than composition. adb took a few minutes to come up on that boot. Bluetooth aborts (`bt_hci_ != nullptr`): no BT HAL yet.

Notes:
- Earlier, USB dropped to MTP only (0955:7102) and adb disappeared while Android was crash-looping; not seen since the binder fix (8).
- `adb root` does not work without "Rooted debugging" in the settings.
- The persisted logcat (`/data/misc/logd`) survives a forced power-off only up to its last rotation; read it from the mini recovery with `rootrun` (mount UDA read-only).

After 4, init gets through early-init: apexd mounts the APEX packages on loop devices (`LOOP_SET_BLOCK_SIZE` fails without consequences), linkerconfig runs, and the tablet stays up with the USB gadget (adb, MTP) enumerated. Not fatal, to look at later: no blkio, memcg or cgroup v2 controllers (`libprocessgroup` warnings), `/acct` read-only, `ueventd.rc` lines with the `net_bt_stack` gid and a 4-field `/sys/` entry.
